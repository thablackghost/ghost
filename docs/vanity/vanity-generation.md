# Vanity Address Generation

## What is a Vanity Address?

A vanity address is a Solana public key that contains a specific pattern. For GHOST token, the program ID is:

```
Gh0st111111111111111111111111111111111111111
```

The prefix "Gh0st" (5 base58 characters) was intentionally generated, with the remaining characters filled by "1" (the base58 encoding of zeros).

## Algorithm

### Brute Force Search

The vanity address is generated by repeatedly generating random keypairs until one produces a public key matching the desired pattern.

```
1. Generate random 32-byte seed
2. Create Ed25519 keypair from seed
3. Encode public key as base58
4. Check if base58 string starts with "Gh0st"
5. If yes → FOUND
6. If no → GOTO 1
```

### Base58 Character Set

Solana uses Bitcoin-style Base58 encoding:

```
Characters: 123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz
(Omitted: 0, O, I, l — to avoid visual confusion)
```

### Why "G" as First Character?

Solana public keys have a fixed first character distribution:
- The first byte of a 32-byte Ed25519 public key determines the base58 prefix
- 'G' is the most common first character for Solana addresses
- This slightly improves the search probability

## Complexity Estimate

### Search Space

For a prefix of length N in base58 (58 characters):

```
Probability = 1 / 58^N
Expected attempts = 58^N
```

### GHOST Prefix

| Prefix | Length | Probability | Expected Attempts | Time (CPU) | Time (GPU) |
|--------|--------|-------------|-------------------|------------|------------|
| "G" | 1 | 1/58 | 58 | < 1ms | < 1ms |
| "Gh" | 2 | 1/3,364 | 3,364 | < 1s | < 1ms |
| "Gh0" | 3 | 1/195,112 | 195,112 | ~1s | < 1ms |
| "Gh0s" | 4 | 1/11,316,496 | ~11M | ~60s | < 1s |
| "Gh0st" | 5 | 1/656,356,768 | ~656M | ~60 min | ~10s |
| "Gh0st1" | 6 | 1/38,068,692,544 | ~38B | ~40 hrs | ~10 min |
| "Gh0st11" | 7 | 1/2,207,984,167,552 | ~2.2T | ~100 days | ~6 hrs |

### GHOST Implementation

The GHOST program ID has 5 matching characters ("Gh0st") with the rest being "1" (zeros). This was chosen as a balance between:
- **Recognizability**: 5 characters is enough to be unique
- **Feasibility**: Computable on a GPU in reasonable time
- **Practicality**: The remaining "1"s make the address easy to identify

## Generation Tools

### Solana Vanity CLI

```bash
# Install
cargo install solana-vanity

# Generate address with "Gh0st" prefix
solana-vanity --prefix Gh0st --output-file ghost-keypair.json

# With GPU acceleration (CUDA)
solana-vanity --prefix Gh0st --gpu --output-file ghost-keypair.json

# Multi-threaded CPU
solana-vanity --prefix Gh0st --threads 16 --output-file ghost-keypair.json
```

### Custom Script (Rust)

```rust
use solana_sdk::signature::{Keypair, Signer};
use rand::rngs::OsRng;

fn main() {
    let prefix = "Gh0st";
    let mut attempts: u64 = 0;
    let start = std::time::Instant::now();

    loop {
        let keypair = Keypair::generate(&mut OsRng);
        let pubkey = keypair.pubkey().to_string();
        attempts += 1;

        if pubkey.starts_with(prefix) {
            let elapsed = start.elapsed();
            println!("Found after {} attempts in {:?}", attempts, elapsed);
            println!("Public Key: {}", pubkey);
            println!("Keypair JSON: {}", keypair.to_base58_string());
            std::fs::write(
                "ghost-keypair.json",
                serde_json::to_string_pretty(&keypair).unwrap(),
            ).unwrap();
            break;
        }

        if attempts % 1_000_000 == 0 {
            let rate = attempts as f64 / elapsed.as_secs_f64();
            println!("Attempts: {} ({} keys/sec)", attempts, rate as u64);
        }
    }
}
```

## Security Considerations

### Is the Private Key Secure?

**YES.** The private key is a standard Ed25519 keypair. The "vanity" aspect only affects the public key encoding. The private key is:
- Generated from cryptographically secure randomness
- Standard Ed25519 (same as any Solana keypair)
- No weaker than a non-vanity keypair

### Statistical Properties

The search process does not weaken the key:
- Each attempt is independent (random 32-byte seed)
- The private key is not constrained (full 32-byte entropy)
- Finding the pattern doesn't reveal any information about the private key
- The key is as secure as any randomly generated keypair

### Verification

1. The keypair can be imported into any Solana wallet
2. `solana-keygen verify <pubkey> <keypair.json>` confirms the match
3. The private key signs transactions normally

## Usage

### Keep the Keypair Secure

```bash
# The generated keypair file
ghost-keypair.json

# Store it securely!
# This is the ONLY key that can deploy to Gh0st1111...
# Without it, the program ID cannot be used
```

### Verification

```bash
# Verify the keypair matches the program ID
solana-keygen verify \
  Gh0st111111111111111111111111111111111111111 \
  ghost-keypair.json

# Expected: "Verification succeeded"
```

### Deployment

The keypair is used ONLY for program deployment:

```bash
solana program deploy target/deploy/ghost_token.so \
  --program-id ghost-keypair.json
```

After deployment, the keypair should be stored in cold storage.

## Why a Vanity Address?

| Reason | Explanation |
|--------|-------------|
| **Brand identity** | "Gh0st" prefix makes the program instantly recognizable |
| **Fraud prevention** | Users can verify they're interacting with the real program |
| **Memorability** | Easier to verify visually than a random address |
| **Trust** | Shows intentional creation, not a random deploy |
| **Meme culture** | Fits the GHOST meme token theme |

## Verification by Third Parties

Anyone can verify the vanity address is genuine:

1. The address is a valid Ed25519 public key (first character 'G')
2. It follows the base58 character set
3. It's 44 characters long (standard Solana address length)
4. The probability of a random address starting with "Gh0st" is ~1 in 656 million
5. The intentional creation is acknowledged by the team
